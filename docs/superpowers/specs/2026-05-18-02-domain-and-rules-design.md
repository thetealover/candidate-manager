# Candidate Manager — Domain and Business Rules

**Status:** Approved
**Date:** 2026-05-18
**Scope:** The `domain` module: aggregates, value objects, the candidate state machine, and the eligibility rules.

## Aggregate root: `Candidate`

A `Candidate` is the only aggregate. Its identity is `CandidateId` (UUID v4, generated by the domain). It owns its collection of `PriorExamPass` entries.

### Fields

| Field | Type | Notes |
|---|---|---|
| `id` | `CandidateId` | Generated at registration. |
| `fullName` | `FullName` | Value object. |
| `email` | `Email` | Value object; normalized to lowercase / trimmed. |
| `dateOfBirth` | `DateOfBirth` | Value object; must be a plausible past date. |
| `educationBackground` | `EducationBackground` | Degree + years of experience. |
| `programLevel` | `ProgramLevel` | `LEVEL_I`, `LEVEL_II`, or `LEVEL_III`. |
| `priorPasses` | `List<PriorExamPass>` | Defensive copy via `List.copyOf`. |
| `registeredAt` | `Instant` | Set by the domain via injected `Clock`. |
| `eligibilityStatus` | `EligibilityStatus` | State machine — see below. |
| `deletedAt` | `Instant` (nullable) | Set by `softDelete()`. |

### Factories

- `Candidate.register(fullName, email, dob, education, programLevel, priorPasses, clock)` — creates a fresh candidate. Status starts at `NOT_VERIFIED`. `registeredAt` set from `clock.instant()`.
- `Candidate.rehydrate(id, fullName, email, dob, education, programLevel, priorPasses, registeredAt, status, deletedAt)` — reconstruction from persistence. Bypasses no invariants; values must already be valid (the mapper is the only legitimate caller).

### Behaviors (state transitions)

- `startVerification()` — moves status to `VERIFICATION_IN_PROGRESS`. Allowed from `NOT_VERIFIED` and from any terminal status (re-trigger). Forbidden if `isDeleted()`.
- `applyDecision(EligibilityOutcome)` — moves status to the terminal value (`ELIGIBLE`, `INELIGIBLE`, or `FAILED`). Allowed only from `VERIFICATION_IN_PROGRESS`. Throws `IllegalStateException` otherwise.
- `softDelete()` — sets `deletedAt` from `clock.instant()`. Allowed only when not already deleted; double-delete throws `IllegalStateException`.

All mutating behaviors throw `IllegalStateException` when invoked on a deleted candidate.

## State machine

```
                  ┌───────────────────────────────────────┐
                  │                                       │
                  ▼                                       │
            NOT_VERIFIED ──startVerification()──► VERIFICATION_IN_PROGRESS
                                                          │
                                                          │ applyDecision()
                                                          ▼
                                  ┌─────────────┬─────────┴───────┬─────────────┐
                                  ▼             ▼                 ▼             │
                              ELIGIBLE     INELIGIBLE         FAILED            │
                                  │             │                 │             │
                                  └─────────────┴─────────────────┴── startVerification() ─┘
```

`FAILED` is distinct from `INELIGIBLE`: `FAILED` means the evaluation itself errored (e.g. unexpected exception in the rules engine), not that the candidate doesn't meet criteria.

## Value objects

All value objects are Java `record` types (immutable, equals/hashCode by value). Compact constructors enforce invariants.

### `Email`
- Trims and lowercases input on construction.
- Validates against an RFC-5321-style regex strict enough to reject `no-at-sign`, `missing@tld`, `@example.com`, and whitespace-containing inputs while accepting common forms like `bob.baker+tag@example.co.uk`.
- Rejects null (`NullPointerException`) and blank/invalid (`IllegalArgumentException`).

### `FullName`
- Two strings: `firstName`, `lastName`.
- Trims; rejects blank / null with `IllegalArgumentException` (consistent message style: `"firstName must not be blank"`).

### `DateOfBirth`
- Rejects `today` and future dates.
- Rejects implausibly old dates (> 130 years ago).

### `EducationBackground(HighestDegree degree, int yearsExperience)`
- `degree` must be non-null.
- `yearsExperience` must be `>= 0`.
- Exposes `meetsLevelOneEligibility()`: `true` if `degree` is `BACHELOR`/`MASTER`/`DOCTORATE`, **or** `yearsExperience >= 4`.

### `PriorExamPass(ProgramLevel level, LocalDate passedOn)`
- Rejects future `passedOn`.
- Exposes `passedWithin(Period window)`: returns `true` if `passedOn` is on or after `today - window`. Boundary at exactly `window` years ago is **inclusive** (a pass exactly 5 years ago today still counts).

### `CandidateId`
- Wraps a `UUID`. Factory `CandidateId.generate()` returns a random UUID. Equality by UUID value.

## Enums

- `HighestDegree { HIGH_SCHOOL, BACHELOR, MASTER, DOCTORATE }`
- `ProgramLevel { LEVEL_I, LEVEL_II, LEVEL_III }`
- `EligibilityStatus { NOT_VERIFIED, VERIFICATION_IN_PROGRESS, ELIGIBLE, INELIGIBLE, FAILED }`
- `EligibilityOutcome { ELIGIBLE, INELIGIBLE, FAILED }` — the three terminal outcomes the rules engine may produce.

## Business rules: `EligibilityRules.evaluate(Candidate) → RuleEvaluation`

`RuleEvaluation` is a value object with two fields: `outcome` (`EligibilityOutcome`) and `reason` (human-readable, English). The `reason` is what gets written to the audit table's `why` column and is shaped so an investigator reading the audit row can understand the decision without re-running the rules.

### Rule R1 — Level I

A `LEVEL_I` candidate is eligible iff `educationBackground.meetsLevelOneEligibility()` is `true`.

- Eligible reason: `"Level I eligibility: candidate holds at least a bachelor's degree."` or `"Level I eligibility: candidate has 4+ years of professional experience."` (whichever path satisfied the rule; bachelor takes precedence when both are true).
- Ineligible reason: `"Level I requires a bachelor's degree or 4+ years of professional experience."`

### Rule R2 — Level II

A `LEVEL_II` candidate is eligible iff `priorPasses` contains a `LEVEL_I` pass that occurred within the last 5 years (inclusive of exactly-5-years-ago).

- Eligible reason: `"Level II eligibility: candidate passed LEVEL_I on <date>."`
- Ineligible reason (no prior pass): `"Level II requires a LEVEL_I pass; candidate has no record of one."`
- Ineligible reason (stale pass): `"Level II requires a LEVEL_I pass within 5 years; latest pass on <date> is outside the window."`

### Rule R3 — Level III

A `LEVEL_III` candidate is eligible iff `priorPasses` contains a `LEVEL_II` pass within the last 5 years (inclusive).

Reasons follow the same shape as R2, substituting `LEVEL_III` / `LEVEL_II`.

### Failure path

If the rules engine throws (e.g. unexpected null in a freshly-loaded aggregate), the use case catches the throwable and `applyDecision(FAILED)` is invoked with a `RuleEvaluation` carrying `reason = "Evaluation failed: " + throwable.message`. This path exists so a misbehaving rules implementation cannot strand a candidate in `VERIFICATION_IN_PROGRESS`.

## Domain events

Events live in `domain` (as plain records) because they are part of the domain's vocabulary. The *publisher* port (`EligibilityEventPublisher`) is also a domain interface; its adapter lives in `infrastructure`.

- `EligibilityRequestedEvent(candidateId, correlationId, actorId, requestedAt)`
- `EligibilityDecidedEvent(candidateId, outcome, reason, decidedAt, correlationId, actorId)`

The audit row is written from `EligibilityDecidedEvent` only — `EligibilityRequestedEvent` exists purely to hand off async work and is not audited.

## Ports (interfaces the outside world implements)

```java
package com.thetealover.candidate.domain.port;

public interface CandidateRepository {
  CandidateId nextId();                                // delegates to CandidateId.generate()
  Optional<Candidate> findActiveById(CandidateId id);
  boolean existsActiveByEmail(Email email);
  Page<Candidate> searchActive(SearchCriteria criteria, Pageable pageable);
  void save(Candidate candidate);                       // insert or update
}

public interface EligibilityAuditRepository {
  void append(EligibilityAuditEntry entry);
}

public interface EligibilityEventPublisher {
  void publish(EligibilityRequestedEvent event);
  void publish(EligibilityDecidedEvent event);
}

public interface Clock {
  Instant instant();
}
```

`Page`, `Pageable`, `SearchCriteria` are domain types (plain records) — we don't take a dependency on Spring's or Micronaut's pagination types.

## Invariants (summary)

- A `Candidate` cannot exist without a valid `Email`, `FullName`, `DateOfBirth`, `EducationBackground`, and `ProgramLevel`.
- Email uniqueness across active candidates is enforced at the **database** layer (partial unique index) and asserted at the application layer (`existsActiveByEmail` check in `RegisterCandidateUseCase`) to fail fast with a friendly error.
- A deleted candidate is immutable. Any state-changing call throws `IllegalStateException`.
- State transitions are total: every status has a defined set of allowed transitions; everything else throws.
- `priorPasses` is treated as an immutable collection inside the aggregate.

## Out of scope

- Updating a candidate's personal details after registration. The brief does not specify it; designing it now would be speculative.
- Modeling certification *holdings* (someone who has *passed* Level I, II, III currently). `priorPasses` is provided at registration as evidence for level eligibility — it is not a service we maintain.
- Multiple programs per candidate. Each registration is for a single `ProgramLevel`.
